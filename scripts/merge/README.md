# `merge/` — combine all component schemas into one provider schema

> **Pipeline stage 3** (see [`scripts/README.md`](../README.md)). `merge_schemas.go`.
>
> | | |
> |---|---|
> | **Runs from** | `provider/` (cwd) |
> | **Reads** | `provider/base-schema.json` (the skeleton) + every `provider/<cloud>/<resource>/schema.json` |
> | **Writes** | `provider/schema.json` — the single merged schema |
> | **Invoked by** | `go run build.go merge` (and every build, since `registry` and all `gen-sdk` targets depend on it) |
> | **Why** | Pulumi's `gen-sdk` and the provider both consume *one* schema; this assembles it from the per-component pieces |

## What it does

`provider/schema.json` is the **single source of truth** that everything
downstream reads (the provider binary, `pulumi package gen-sdk`, the SDK
post-processors). It is **generated**, never hand-edited. This script builds it.

It starts from `provider/base-schema.json` — the skeleton holding everything
that isn't a component:

- top-level package metadata (`name`, `version`, `description`, `license`,
  `homepage`, `repository`, `publisher`),
- the `language` block (per-language SDK config: package names, dependencies,
  `pyproject.enabled`, Go import path, etc.),
- shared top-level `types` (e.g. `anvil:index:ComplianceFramework`).

Then it walks every `provider/<cloud>/<resource>/schema.json` and merges each
one's `resources` and `types` into the skeleton. The result is written to
`provider/schema.json`.

## How it works

```
base-schema.json  ──►  masterSchema (in memory)
                         │
   for each provider/<cloud>/<resource>/schema.json:
       masterSchema.resources += fragment.resources
       masterSchema.types     += fragment.types
                         │
                         ▼
                  provider/schema.json
```

Key properties:

- **Base is preserved verbatim.** Every top-level key in `base-schema.json` flows
  through untouched — which is why adding metadata or the `language` config there
  reaches all SDKs. Only `resources`/`types` are *added* to.
- **Auto-discovery.** It scans `provider/` for `<cloud>/<resource>/schema.json`
  (skipping `cmd`, `scripts`, `sdk`). No registration list — drop a component
  folder in and it's merged.
- **Last write wins** per `resources`/`types` key (component fragments shouldn't
  collide; they namespace by token like `anvil:aws:Bucket`).

## Adding a new component

Nothing to do here — `merge` auto-discovers any `provider/<cloud>/<resource>/schema.json`.
Just make sure the component's schema exists (authored by hand, or generated by
[`generate-site-schemas/`](../generate-site-schemas/README.md) /
[`generate/`](../generate/README.md)).

## Editing package-wide things

To change SDK metadata, dependencies, the version, or a language's packaging,
edit **`provider/base-schema.json`** — `merge` carries it into
`provider/schema.json` for you.

## Gotchas

- `scripts/merge/schema.json` is a **stale sample** from an old PR — *not* read by
  this script (which reads `base-schema.json` from its `provider/` cwd). Safe to
  delete.
- Because the output is fully regenerated each run, never hand-edit
  `provider/schema.json` — your change will be overwritten on the next build.
